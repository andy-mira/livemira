## 相对 0.5.0-rc.2

- **目标图评分独立成模块** `files/livemira-target-rating.min.mjs`（离线包 `@livemira/target-rating`，{{ratingKb}} KB，不上 npm）：不需要引擎，在自己的 Worker 里按引擎的方式编译图片并打分，可直接用在作品编辑页这类不开相机的页面。`rateTargetImage(图片文件)` 或 `rateTarget(已编译的目标)`，评分结果与 rc.2 相同。说明见 `documentation/target-rating.zh-CN.md`。
- **引擎只保留核心**：`rateTarget` 移出引擎；真机测试套件用的诊断（帧条、逐帧跟踪记录、方向缩略图）在发布构建中被编译掉；视觉 Worker 不再逐帧估计没人用的 6 自由度位姿。引擎因此从 rc.2 的 130 KB 降到 {{engineKb}} KB。
- 评分与引擎分开构建，`release-manifest.json` 的 `modules` 分别列出两者的构建 ID：评分的改动不会改变引擎文件。
- 产品代码中的过时注释（内部阶段代号、设计文档编号）已改为直白说明；选型阶段的原型引擎从产品包移到测试侧。
- 示例的评分页改用评分模块，不再加载引擎。

## 相对 0.5.0-rc.1

- 照片在画面中较小时不再频繁丢失：跟丢后先在原位附近找（最多 2 秒，范围随时间扩大），小照片的区域放大至多 3 倍再取特征。
- 默认用相机原尺寸识别（`camera.processingScale`，可选 3/4、1/2）。iPhone 上原尺寸 4 种显示方式 0 次丢失，1/2 为 6 次。
- 新增目标图评分；示例的识别图页改为每页一张、左右翻页。

## 相对 0.4.1

- **引擎**：新一代识别与跟踪，帧锁定合成。
  - 档位 Swift（默认）/ Hawk / Wren，按设备能力回退；
  - 不支持 WebGL2 的设备不识别，并提示。
- **照片上的呈现**：全部在 WebGL2 中与相机画面同帧绘制，透视正确，不会漂移。
  - 识别时边缘亮起一次光晕；
  - 视频边下边播；识别后立即出现视频比例的半透明黑色区域，中间转圈；
  - 视频能播放时，从区域中心向四周展开，边缘带光亮的波前。
- **相机界面**：接口与 0.4.1 兼容，内部重写。
  - 带百分比的加载卡片；
  - 照片编译与打开相机同时进行；
  - 扫描引导框；
  - 识别时轻振；
  - 视频下载进度（整段下载时）。
- **目标图评分**：独立模块 `livemira-target-rating`，取代 0.4.1 的 `livemira-target-quality`。
- **大小**：引擎 {{engineKb}} KB（0.4.1 为 178 KB），相机界面 {{uiKb}} KB，目标图评分 {{ratingKb}} KB。

## 验证

- 单元与集成测试全部通过（`npm run check`）。
- 浏览器端到端测试在桌面 Chromium 与 WebKit 上通过（`node bench/release/e2e.ts`）。视频按约两倍码率限速：Chromium 中视频只下了约两成就开始播放；Playwright 的 macOS WebKit 测试版要等响应全部到达才把数据交给播放器，这一项留给真机确认。测试用合成相机覆盖以下流程：
  - 加载卡片、扫描、识别、视频加载与展开、播放；
  - 声音、退出、照片移开；
  - 无 WebGL2、相机被拒。
- 引擎核心已在真机上通过：iPhone（iOS 27，Safari、Chrome、微信）、POCO F4、三星 A26、Android 10 低端机。10 分钟持续性能比 1.00，静止抖动 0.005 px。
- 产品层（视频平面、加载区域与展开、边下边播、相机界面）已用测试页 ⑨ 在手机上验收（preview.3）；小照片修复与原尺寸识别已用测试页 ⑩（LiveMorae 的演示照片与视频）在 iPhone 上验收；评分已在测试页 ⑪ 上体验确认；rc.2 已集成到 LiveMorae 并通过真机验收。
- 本版相对 rc.2 的改动由单元测试、端到端测试与 LiveMorae 兼容检查覆盖；作品编辑页的评分提示待在 LiveMorae 中真机确认。
